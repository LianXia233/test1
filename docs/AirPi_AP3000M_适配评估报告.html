2. 官方支持状态

OpenWrt 官方 2026-01-20 已合入支持（PR #21397 / #21601，作者 Fil Dunsky），dts 位于 target/linux/mediatek/dts/mt7981b-airpi-ap3000m.dts。

ImmortalWrt master 同步维护该 dts（用户提供链接即官方仓库 master 分支）。

社区配套 已有 luci-app-airpi3000m-fancontrol（LuCI 风扇控制 + Rust 温控守护 + airpi-gpio-fan 内核驱动，LianXia233 维护）。

注意 原厂固件 factory 分区（mmcblk0p2）为空，刷机前需写入 EEPROM：dd if=/lib/firmware/MT7981_iPAiLNA_EEPROM.bin of=/dev/mmcblk0p2 bs=4k count=1，否则无线校准失效。

3.1 内核 / BSP（P0，已有官方支持）

  • 直接采用 ImmortalWrt mediatek/filogic target 现有 dts 与驱动，无需自行移植
  • 板型 overlay：GPIO/LED 已定义；PWM 风扇驱动（airpi-gpio-fan）作为补丁并入内核包
  • eMMC 引导：blob/ATF + U-Boot web 刷机流程保持官方链路

3.2 配置层（P0，libnvram 原型已交付）

  • 持久配置：/etc/config/padavan（UCI 后端）；Debian/裸机环境自动回退文件 KV 后端
  • nvram API 兼容：老毛子插件直接链接 libnvram 无需改代码
  • eMMC 上的配置可靠性高于老毛子 MTD nvram：无分区磨损问题

3.3 服务层（P1，rc-ng）

  • 老毛子 rc 常驻主循环 → procd init 脚本（wan / firewall / dnsmasq / usb 首批）
  • notify_rc → ubus 事件总线

3.4 界面层（P2，luci-app-padavan）

  • 复刻老毛子核心页面；本机已有 luci-app-airpi3000m-fancontrol 可并入

6. 风险与缓解

风险等级缓解措施
2.5G PHY（Realtek C45）驱动在主线内核的稳定性中锁定官方支持 commit；跟进 mtk_eth 与 rtl phy 补丁更新；实测吞吐/回退
MT7976 无线驱动与主线内核耦合中跟随 MTK WiFi feed 版本；升级内核时同步升级驱动
factory 分区 EEPROM 缺失导致无线异常中刷机流程强制写 EEPROM；固件启动自检 nvmem 有效性
老毛子插件对 nvram 私有语义的依赖低libnvram API 兼容 + defaults 表保底
M.2 5G modem 模组兼容性（qmi/rgmii 变体）中按实际模组选用 qmi-wwan/rgmii 方案，预留 pcie 引脚 overlay

7. 结论

AirPi AP3000M 是 Padavan 重写方案的理想首发机型：官方 OpenWrt/ImmortalWrt 支持已合入，硬件画像与老毛子传统功能（USB 存储、VPN、QoS、5G modem）高度契合，且社区已有风扇控制等配套。适配路径清晰：基座零移植 → libnvram 配置层 → rc-ng 服务层 → luci-app-padavan 界面层，全程无需触碰老 MIPS 代码。

建议下一步：在 AP3000M 上编译验证 libnvram 原型（UCI 后端），随后推进 M3 网络链路里程碑。
