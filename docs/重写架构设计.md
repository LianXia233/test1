# rt-n56u（Padavan）重写架构设计 —— 适配 MT7981B / MT7987A

- 文档版本：v0.1（原型阶段）
- 日期：2026-10-08
- 上游参照：hanwckf/rt-n56u master
- 目标平台：MT7981B（Filogic 820）、MT7987A（Hiveton H5000M 同系）

---

## 1. 设计目标与原则

### 1.1 目标

在不依赖老 MIPS 二进制的前提下，把 Padavan（老毛子）的**配置体系、服务模型、管理界面**在 ARM64 + 现代 Linux（ImmortalWrt/OpenWrt 6.x）上重建，做到：

1. 老毛子丰富的家用路由功能（智能 QoS、USB 存储、DDNS、VPN、校园网认证等）以现代工程方式落地
2. nvram 配置语义兼容：老毛子插件/脚本的 `nvram get/set` 习惯可平滑迁移
3. 服务管理现代化：procd（OpenWrt init）+ UCI 驱动，取代老式 rc 常驻主循环
4. 与现有 Hiveton H5000M（MT7987A + eMMC + Debian 13 + 6.x 内核）技术栈兼容可互通

### 1.2 原则

- **API 兼容优先**：对外保持 `nvram_linux.h` 的 13 个 API 签名不变，让老毛子应用代码改动最小
- **配置可迁移**：老毛子 nvram 变量表（`shared/defaults.c` 的 router_defaults）可一键导入导出
- **标准基座**：内核/BSP/无线/加速全部走 ImmortalWrt 主线，不自造轮子
- **渐进式重写**：配置层 → 服务层 → 界面层 → 应用包，逐层替换验证

## 2. 总体架构

```
┌─────────────────────────────────────────────────────────────┐
│                   管理界面层（LuCI 模块）                     │
│   luci-app-padavan（复刻老毛子页面：状态/网络/无线/USB/QoS）  │
├─────────────────────────────────────────────────────────────┤
│                   服务层（procd + rc-ng）                    │
│   procd init 脚本 · 服务注册表 · notify 事件总线             │
│   （替代老毛子 rc 常驻主循环 + notify_rc 机制）               │
├─────────────────────────────────────────────────────────────┤
│                   配置层（nvram-uci 适配库）                  │
│   libnvram-uci：API 兼容 nvram_linux.h                      │
│   ├─ 后端 A：libuci（OpenWrt 原生，/etc/config/padavan）     │

└─────────────────────────────────────────────────────────────┘
```

## 3. 配置体系设计（nvram → UCI）

### 3.1 存储模型

| 老毛子概念 | 重写映射 | 说明 |
|---|---|---|
| nvram（MTD 分区） | `/etc/config/padavan`（UCI） | 持久配置，commit 后生效 |
| nvram temp | `/tmp/padavan.tmp`（KV 文件） | 重启丢失，对应 nvram_set_temp |
| 默认值表（defaults.c） | `libnvram` 内置 defaults 数组 | 从 router_defaults/tables_defaults 自动生成 |
| 配置备份（save/restore） | UCI export/import | `uci export padavan` / `uci import` |

### 3.2 UCI schema（padavan 配置文件）

```uci
# /etc/config/padavan
config 'system' 'router'
	option 'hostname' 'Padavan-MT7987'
	option 'timezone' 'CST-8'
	option 'productid' 'H5000M'

config 'wan' 'wan0'
	option 'proto' 'pppoe'
	option 'username' ''
	option 'password' ''
	option 'dns' '1'

config 'lan' 'lan0'
	option 'ipaddr' '192.168.31.1'
	option 'netmask' '255.255.255.0'
	option 'dhcp_enable' '1'

config 'wifi' 'wl0'
	option 'ssid' 'Padavan-2.4G'
	option 'auth_mode' 'psk2'
	option 'wpa_psk' ''

config 'usb' 'storage'
	option 'enabled' '1'
	option 'automount' '1'
```

> 兼容策略：`nvram_get("wan0_proto")` 内部映射为 UCI 路径 `padavan.wan0.proto`。命名规则：nvram 名 `section_key` → UCI `padavan.section.key`；无下划线变量归入 `padavan.misc.<name>`。默认值缺失时回退 defaults 表。

### 3.3 API 映射表

| nvram_linux.h API | libnvram-uci 实现 |
|---|---|
| `nvram_get(name)` | UCI 读 `padavan.<sec>.<key>` 或 defaults 回退 |
| `nvram_safe_get(name)` | 同上，NULL 时返回 `""` |
| `nvram_get_int(name)` | 读值 `atoi` |
| `nvram_safe_get_int(name,d,min,max)` | 带默认值/范围钳制 |
| `nvram_getall(buf,count,include_temp)` | 遍历 UCI 全部 option，拼 `k=v\0` 数组 |
| `nvram_set(name,value)` | UCI 写（暂存，未 commit） |
| `nvram_set_int(name,val)` | 同上 |
| `nvram_unset(name)` | UCI delete |
| `nvram_set_temp(name,value)` | 写 `/tmp/padavan.tmp` |
| `nvram_set_int_temp(name,val)` | 同上 |
| `nvram_match(name,match)` | 读值后 strcmp |
| `nvram_invmatch(name,match)` | 读值后 strcmp 取反 |
| `nvram_commit()` | `uci commit padavan` |
| `nvram_clear()` | 清空 padavan 配置并恢复 defaults |

## 4. 服务模型（rc → procd）

### 4.1 服务注册表

老毛子 `rc/services.c` 的 `service_do()` 大 switch 拆解为**服务描述表**：

```c
struct padavan_service {
    const char *name;          /* "dnsmasq" */
    const char *uci_section;   /* "padavan.dnsmasq" */
    const char *procd_script;  /* "/etc/init.d/padavan-dnsmasq" */
    int  (*enabled)(void);     /* 从 UCI 判断是否启用 */
    void (*reload)(void);      /* 热重载回调 */
    int  depends[4];           /* 依赖服务 */
};
```

### 4.2 procd 骨架（示例）

```sh
#!/bin/sh /etc/rc.common
# /etc/init.d/padavan-dnsmasq
USE_PROCD=1
START=90
STOP=10

start_service() {
    local enabled="$(uci -q get padavan.dnsmasq.enabled)"
    [ "$enabled" = "1" ] || return 0
    procd_open_instance
    procd_set_param command /usr/sbin/padavan-dnsmasq
    procd_set_param respawn
    procd_close_instance
}
reload_service() {
    /usr/sbin/padavan-dnsmasq --reload
}
```

### 4.3 notify 事件总线

老毛子 `notify_rc`（写 `/tmp/notify_rc` + 信号触发 rc 主循环）重写为 **ubus 事件**：

| 老毛子 | 重写 |
|---|---|
| `notify_rc("restart_firewall")` | `ubus call padavan event '{"action":"restart_firewall"}'` |
| rc 主循环轮询 | ubus 监听 + procd 服务编排 |

## 5. 管理界面策略

- **首选**：LuCI 模块 `luci-app-padavan`，逐页复刻老毛子功能（系统状态、无线、WAN/LAN、USB、QoS、插件）
- **备选**：保留老毛子 httpd 的 `ej` 模板思路，但换现代嵌入式 Web 框架（uhttpd + Lua/JS）
- **迁移工具**：老毛子 `nvram show` 导出 → `padavan-migrate` 脚本转 UCI

## 6. 内核 / BSP 策略

| 模块 | 方案 |
|---|---|
| 内核 | ImmortalWrt 6.6/6.18 target `mediatek/filogic`（MT7981B 官方支持；MT7987A 用现有补丁序列，参照 LianXia233/test） |
| 设备树 | 复用 ImmortalWrt mt7981/mt7987 dts，按板型 overlay（GPIO、LED、USB 供电） |
| 无线 | MTK WiFi feed（mt76 hybrid），不碰老毛子 rt_wifi |
| 硬件加速 | mtk_ppe + hnat，DSA 交换，不碰老毛子 rt_ppe |
| 存储 | MT7981B：ubi；MT7987A：eMMC + ubifs（沿用 H5000M 方案） |

## 7. 模块重写清单

| 老毛子模块 | 重写方式 | 优先级 |
|---|---|---|
| shared/nvram_linux.c | **libnvram-uci**（API 兼容） | P0 |
| shared/shutils.c | 移植 + 去 MIPS 依赖 | P1 |
| rc/init.c + rc/net*.c | rc-ng（procd 服务编排） | P1 |
| rc/services.c | 服务注册表 + ubus 事件 | P1 |
| rc/watchdog.c | procd respawn + watchdog 脚本 | P2 |
| httpd/* | luci-app-padavan | P2 |
| user/ 应用包 | OpenWrt feed 打包为 ipk | P2 |
| 内核 BSP | ImmortalWrt 主线 + 板型 overlay | P0（基座） |

## 8. 迁移路径与里程碑

- **M1（本原型）**：libnvram 文件后端 + API 兼容层 + procd 骨架示例 + 架构文档
- **M2**：libnvram UCI 后端 + defaults 表自动生成 + nvram 命令 CLI 兼容（`nvram get/set/show/commit`）
- **M3**：rc-ng 服务编排（dnsmasq/firewall/wan 首批）+ notify→ubus 桥
- **M4**：luci-app-padavan 首屏（状态/网络/无线）
- **M5**：USB 存储、QoS、VPN、DDNS 等应用包迁移；MT7981B 与 MT7987A 双板型验证

## 9. 风险与缓解

| 风险 | 缓解 |
|---|---|
| MT7987A 上游补丁漂移（内核 6.18 结构体变更） | 锁定 ImmortalWrt commit；移植补丁前 grep 核验结构体成员（已有踩坑经验） |
| 老毛子应用依赖 nvram 私有语义 | API 兼容层 + defaults 表保底，迁移工具核对变量引用 |
| 无线 hybrid 驱动与主线内核耦合 | 跟随 MTK feed 版本，升级内核同步升级驱动 |
| Debian 13 无 libuci | 双后端设计：Debian 用文件后端，ImmortalWrt 用 libuci 后端 |
